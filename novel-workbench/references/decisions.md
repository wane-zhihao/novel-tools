# 无人值守默认决策表（decisions.md）

铁律：**禁止向用户提问或请求确认**。遇到分歧按本表取默认值，记入 `state.json` 的
`decisions_taken`（格式 `{at_node, issue, applied_rule}`）后继续走。
只有三种情况允许停：脚本硬失败 / 闸门 BLOCK / 用户明确喊停。

| # | 场景 | 默认决策 |
|---|---|---|
| D01 | 选题打分出现平手 | 取「平台收稿匹配度」最高者；仍平手取榜单热度高者 |
| D02 | 配角重名 | 取先登场者，后登场者改名（保留姓氏） |
| D03 | 设定之间冲突（角色年龄 vs 时间线等） | 以时间线为准改角色，角色服务于事件 |
| D04 | judge 打回，但修复指令指向已封板的前序章 | 按「只改当前章」降级执行；无法降级则判 block 并说明 |
| D05 | 细纲某字段暂定不了 | 写 `[待补充]`；但「目标情绪」「主角目标/关键选择」两项必须写实际内容 |
| D06 | 正文字数低于 2000 硬卡 | 进 N14 定点补写，不许注水凑字数；同一处 2 次不过 → blocked |
| D07 | 创作直觉与文风基准冲突 | 服从 `harness/genre-baselines.json` 的年代组基准 |
| D08 | 脚本连续超时/失败 | 不重试第三次，直接 blocked 并保留现场 |
| D09 | token 不匹配或节点不匹配 | 视为越权调用，停止并报 blocked，不准猜 token |
| D10 | 12 章骨架写完但总字数不足 2 万 | 按 `max_chapters` 继续写下一章，直到达标或触上限 |
| D11 | N15 判定 block 且无法定位到当前章 | 记入 `pending_questions`，blocked 停机，等人工或下一轮 resume |
| D12 | 探针/闸门工具本身缺失或崩溃 | 按工具自身降级规则处理；整条链断则 blocked，不静默跳过 |
