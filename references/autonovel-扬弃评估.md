# autonovel 扬弃评估

> 调研对象：`https://github.com/NousResearch/autonovel`（Nous Research，Python，27 个脚本）
> 调研日期：2026-10-23 ｜ 目的：判断能否扬弃以优化本工作台

---

## 一、它是什么

从一颗种子概念出发，自动写完一部小说，并产出**印刷级 PDF / ePub / 有声书 / 落地页**。
首部验证作品《The Second Son of the House of Bells》，19 章 79,456 词。
灵感来自 `karpathy/autoresearch`——把「修改-评估-保留/丢弃」的自动研究循环搬到小说创作。

---

## 二、最关键的一条：目标函数不同，不能整体照搬

| | autonovel | 我们 |
|---|---|---|
| 目标 | **文学出版质量**（Opus 扮演文学评论家 + 小说教授） | **七猫签约过审**（编辑一眼不毙 + 算法数据） |
| 评判者 | 文学批评视角 | 商业连载视角 |
| 篇幅 | 79k 词 / 19 章 | 20k 字 / 10 章（签约门槛） |
| 交付 | PDF / ePub / 有声书 / 落地页 | 单文件正文 + 投稿邮件 |
| 平台规则 | 无 | 七猫判定清单 7 大类 21 条 |

**两者会冲突。** 他们奖赏「prose texture / subtext / voice earned」，七猫奖赏「前 200 字有冲突 + 爽点密度 + 主线清晰」。
若把他们的评分当优化目标，会把稿子推向「文学」而远离「过签」。

**结论：取它的机器，弃它的目标函数。**

## 三、逐项扬弃表

### ✅ 值得取（机器与机制）

| # | 它有什么 | 我们的现状 | 价值 |
|---|---|---|---|
| 1 | **TELLING_PATTERNS** 正则：`(he\|she) felt (angry\|sad...)` 直接判「展示变讲述」 | 只有散文级规则「不要写他感到一阵」，**没有正则，无法自动判** | **高** |
| 2 | **transition_opener_ratio**：段落首词是过渡词的比例 | 无 | 中（AI 腔的强信号） |
| 3 | **tier2 聚类**：单个可疑词不报，**同段出现 ≥3 个才标记** | 我们的词表是「命中即报」，误报率高 | **高**（降误报） |
| 4 | **对抗性删减**：让 judge 强制「删 500 词」，**删单即修订计划** | N14 只修 findings，**从不强制删** | **高** |
| 5 | **Elo 瑞士制锦标赛**：章节两两对比排名，找出最弱的章 | 无跨章质量比较 | 中 |
| 6 | **reader_panel 4 人格**：编辑 / 类型读者 / …，**分歧处才是编辑决策点** | 只有单一 judge | **高** |
| 7 | **plateau detection**：分数稳定就停修订循环 | 固定 2 轮，盲目 | **高** |
| 8 | **propagation debts**（`state.json` 的 `debts: []`）：五层双向传播的欠债账本 | 我们有五层（设定/卷纲/细纲/正文/追踪）但**完全没有传播追踪** | **最高** |
| 9 | **双免疫系统**：机械层（无 LLM）+ LLM 裁判层，且**裁判用更强的模型**（Opus vs Sonnet），"Intentionally different to avoid self-congratulation" | 我们有机械层 + judge，但**judge 与 writer 同模型** | **高**（这是我们真实弱点） |
| 10 | **0–10 分数量表**（foundation >7.5、chapter >6.0） | 只有 pass/fail，没有程度 | 中（plateau/Elo 的前提） |

### ❌ 不能取（附理由）

| 项 | 为什么不要 |
|---|---|
| `TIER1_BANNED` / `TIER2_SUSPICIOUS` 英文词表 | 全是 `delve / utilize / leverage / tapestry / myriad`，**对中文零价值**。我们的对应物是 `banned-words.md` 里已有的中文词表 |
| LaTeX 排版 / ePub / 有声书 / 落地页 | 我们投七猫网页，只需单文件正文。**这四项占了它 27 个脚本里的 8 个** |
| Claude API 直调（`ANTHROPIC_API_KEY`） | 我们跑在 WorkBuddy subagent 上，不走 API |
| Opus 双角色审阅的具体提示词 | 提示词绑定「文学评论家 + 小说教授」，与七猫标准冲突。**只取「双角色 + 有条件停止」的机制** |
| 19 章 / 79k 词的规模设定 | 七猫 2 万字就能签，写多反而拖 |

## 四、建议落地的 5 项（按性价比排序）

### ① 传播债务账本（最高优先，架构缺口）

它用 `state.json` 的 `debts: []` 记录「改了下游，上游还没同步」。
我们的五层之间完全没有这个机制——**改了第 3 章正文里的人名，`设定/角色.md` 和 `追踪/` 不会自动标记待更新**。

落地：`autopilot.py` 的 `state.json` 加 `debts: []`，每个 `done` 时检查是否触及跨层字段（人名/地名/时间/伏笔），有则记一条债务；`resume` 时先清债。

### ② 对抗性删减（性价比最高，直接治我们的病）

它的核心洞察：**「删什么」比「改什么」更能暴露弱点，删单本身就是修订计划。**

我们的实测数据支持这一条：《重回七九年》数字密度 67/千字 vs 签约作品 0，动作词 51 vs 44.76——
**问题不是「写得不好」，是「该删的没删」**。而我们的 N14 只会「补因果、加描写」，从不删。

落地：`C{n}.N14` 增加一轮「强制删 8%」——judge 给出删除清单（原句 + 理由），writer 只删不增。

### ③ TELLING_PATTERNS 中文化（补我们的盲区）

我们规则里写了「不许写他感到一阵……」，但**没有任何脚本能检测它**。
中文化正则示例：`(他|她|众人)(感到|觉得|心里)(一阵|十分|非常)?(愤怒|难过|害怕|紧张|激动|羞愧|委屈|绝望)`。

落地：`clarity_org_probe.py` 加 `telling_per_1000`，先作为 advisory 观察，有区分力再升 B。

### ④ reader_panel 4 人格（治「judge 与 writer 同模型」）

我们用同一模型写和审，这是真实弱点。它用 Opus 审 Sonnet 写。
我们换不了模型，但**换人格 + 多角色分歧**能部分补偿：4 个 subagent 各持不同视角，
**分歧最大的那一条才是真问题**（一致通过的反而可能是盲区）。

落地：`C{n}.N15` 从 1 个 judge 改为 4 个（七猫编辑 / 追更读者 / 同行作者 / 挑刺读者），取分歧项。

### ⑤ plateau detection（治盲目 2 轮）

我们固定「同处失败 2 次就 blocked」，它用「分数稳定即停」。
落地：N14/N20f 的循环条件从「固定 2 轮」改为「连续两轮分数变化 <0.5 即停，上限 3 轮」。

## 五、不推荐的

- **Elo 锦标赛**：需要 ≥8 章才有统计意义，我们首批 10 章勉强够，但收益不如前五项直接。**列为三期可选。**
- **0–10 分数量表**：是 plateau 与 Elo 的前提。若做 ⑤ 则必须做它；若不做 ⑤ 则不必。

---

## 六、结论

**扬弃判词：**

> 它的**编排机制**（双免疫、对抗删减、多读者分歧、传播债务、平台期早停）值得整体吸收；
> 它的**质量目标**（文学出版标准）与我们的**商业过审目标**相斥，必须弃掉；
> 它的**英文词表与出版流水线**（LaTeX/ePub/有声书/落地页）对中文网文零价值，直接弃。

**最高优先级是第 ①（传播债务）和第 ②（对抗删减）**——前者补一个我们从没建过的架构层，
后者直接对准我们实测出来的真病根（数字与动作堆叠，而非文笔）。
