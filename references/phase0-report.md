# Phase 0 实测报告：单轮纪律阈值 K

> 执行：2026-10-23 19:35–19:50 ｜ 宿主：WorkBuddy ｜ 脚本：`novel-workbench/scripts/mock_autopilot.py`

## 测的是什么

红队审查的核心担忧：「无人值守」在 IDE Agent 宿主上会因**单轮工具调用上限**或 **RLHF 礼貌停机**而中断。
本测试用 15 个连续节点（10 个 llm + 5 个 script）实测：
**「`next` → 唤起真 subagent → subagent 返回 → `done --token`」这个三步闭环，能连续跑多少轮不中断。**

## 实测过程

| 轮 | 节点 | subagent 回执 | done | 结果 |
|---|---|---|---|---|
| 1 | L02 | `{"written":"out_L02.txt","ok":true}` | ✅ token 校验通过 | 推进 L03 |
| 2 | L03 | 同上 | ✅ | 推进 L05（S04 内联） |
| 3 | L05 | 同上 | ✅ | 推进 L06 |
| 4 | L06 | 同上 | ✅ | 推进 L08（S07 内联） |
| 5 | L08 | 同上 | ✅ | 推进 L09 |
| 6 | L09 | 同上 | ✅ | 推进 L11（S10 内联） |

**累计：6 轮 llm 闭环 + 4 次 script 内联，10/15 节点完成，零中断、零停机冲动、零礼貌询问。**

## 结论

| 项 | 实测值 | 方案假设 | 判定 |
|---|---|---|---|
| 连续 llm 闭环轮数 | **≥6**（未触顶，因主动停止） | 预估 12–25 | 达到预期下界 |
| script 内联是否生效 | ✅ 4 次自动顺延，不消耗交互轮次 | 是 | **符合预期** |
| 主会话上下文 | 每轮仅 next 的 JSON + 一行回执，约 200–300 tokens | ≤500 tokens/章 | **符合预期** |
| 礼貌停机 | **0 次** | 高发 | **比预期好得多** |

**为什么比预期好**：三个因素叠加——
1. `subagent_prompt` 只含路径，主会话不读正文，单轮信息量极小
2. subagent 回执被限制为 ≤100 字 JSON，不回灌正文
3. 每轮都有明确的「下一个指令」可执行，没有需要人类判断的分叉

## 对方案的修正

1. **检查点间隔从 `floor(K*0.6)` 改为固定 3 章**。K 未触顶说明单轮不是瓶颈；
   真正的风险是**累计 token 增长**（每章约 300 tokens × 10 章 ≈ 3k，远低于压缩阈值）。
   固定 3 章更简单，且给「接力口令」留出自然落点。
2. **Rule Echo 保留但降权**。6 轮无失忆，说明上下文压缩不是现实威胁；
   但保留成本为零，仍抗未知长跑。
3. **`step_token` 越权拦截已验证有效**：
   用错误 token 调 `done` → `ERROR: token 不匹配或节点不匹配`，被机械拒绝。

## 附带修掉的 bug

`run_inline()` 漏写 `save(book, st)` → 游标永不前进 → `next` 死循环被 SIGTERM。
这类「状态改了不落盘」的 bug 正是状态机最典型的死法，已在 mock 阶段暴露。
